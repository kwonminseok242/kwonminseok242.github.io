PrismView: 감이 아니라 검증으로 매매하기

시간과 감정이 드는 수동 매매 대신, 직접 만든 지표(ICE)를 규칙으로 만들어 백테스트로 검증했습니다. 2026년 10월부터는 차트 도구 PrismView를 Java로 혼자 다시 만들고 있습니다.

판단: 수동 매매 vs 규칙화·검증

20살부터 매매를 하며 가장 크게 느낀 것은 시간의 제약, 그다음은 감정 소모였습니다. 그래서 직접 만든 데이터 기반 기술적 지표 ICE(Inception Core eXtension)를 규칙으로 옮기고, 트레이딩뷰에서 Pine Script로 백테스트해 검증하는 쪽을 택했습니다. 이 과정에서 코딩을 더 공부하게 됐고 금융권 개발로 진로를 정했습니다.

백테스트 결과이며 실거래 성과가 아닙니다. 기간이 9일로 아주 짧아 충분히 검증됐다고 보기 어렵고, 더 긴 기간으로 다시 검증하는 것이 다음 과제입니다.

지금 만들고 있는 것

  • OKX 1초 캔들 수집기와 30초 집계기 (Java, Spring Boot, PostgreSQL)
  • docker-compose로 PostgreSQL 구성, Flyway로 테이블 관리, 프로필별 DB 설정
  • 이슈 → 브랜치 → PR 단위로 작업 기록
  • 처음 뼈대는 Cursor로 만들었다가 지우고, 직접 하나씩 구현 중

현재는 수집기와 DB 테이블의 뼈대 단계입니다. Java로 만드는 이유는 금융 시스템에서 많이 쓰는 Java 경험을 채우기 위해서입니다.

한계와 배운 점

  • 2024년부터 계획했지만 실력과 시간이 부족해 오래 이어가지 못했습니다.
  • 다시 한다면 무엇을 만들고 싶은지부터 확실히 정하겠습니다. 그게 정해지지 않아 미뤄진 일이 가장 많았습니다.
